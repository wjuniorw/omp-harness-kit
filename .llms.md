# .llms.md — Diagnostic & Bootstrap Meta-Prompt (`omp-harness-kit`)

> **Instrução para Agentes de IA (`omp`, Claude Code, Codex, Opencode, Cursor):**
> Se o usuário pedir *"Leia `.llms.md` e diagnostique/configure meu ambiente"*, execute este playbook de forma determinística, sem expor credenciais/chaves e perguntando ao humano via `ask` (ou prompt estruturado) apenas quando houver decisão real.

---

## 1. Regras de Segurança (Invioláveis)
- **NUNCA** leia, imprima, registre em log ou faça commit de API keys (`OMP_API_KEY`, tokens em `~/.omp/agent/models.yml`, `.env*`).
- Ao testar endpoints (`/v1/chat/completions`), envie requisições com variável de ambiente / substituição em memória e imprima apenas o código HTTP e o ID do modelo retornado.
- Antes de sobrescrever `~/.omp/agent/config.yml` ou `models.yml`, crie backup com timestamp (`.bak.<ts>`).

---

## 2. Fase de Diagnóstico (Somente Leitura)

Execute e colete o estado real antes de propor alterações:

1. **Ferramentas locais**:
   - `omp --version`
   - `node --version` e `npx --version`
   - `python3 --version`
   - `git --version` e `git config user.name` / `git config user.email`
   - `docker --version` (relevante se o usuário for rodar OmniRoute local)
2. **Runtime `omp` em `~/.omp/agent/`**:
   - Verificar existência de `config.yml`, `models.yml`, `agents/spec-critic.md`.
   - Verificar `~/.claude/commands/sdd-loop.md` e `~/.agents/skills/{sigapro-sdd-loop,smoke-test-rounds,the-fool}`.
   - Conferir se `models.yml` ainda possui `sre/triage-combo` (deve ser removido em ambiente dev) ou se `gemini/gemini-4-argon` + `claudio-combo` estão configurados.
3. **Conectividade com Gateway / OmniRoute**:
   - Ler `baseUrl` de `~/.omp/agent/models.yml` (sem imprimir `apiKey`) e checar `GET /models` ou `omp --model ... --no-tools -p --no-session --mode json "Responda apenas: OK"`.
   - Se o usuário ainda não tiver gateway nem OmniRoute local, orientar usando `omniroute/README.md` e `omniroute/omniroute-combos.example.json`.
4. **Projeto alvo (se invocado dentro de um repositório de código)**:
   - Detectar stack (`package.json` Next.js/NestJS/Expo/RN, `go.mod`, `Cargo.toml`, etc.).
   - Verificar existência de `.agent/` (Meta-Harness do projeto: `rules/`, `skills/`, `harness/tools/`), `.agents/skills/`, `.gitignore` (contendo `.agents/`), `skills-lock.json` e `.agent/skills-manifest.json`.
   - Verificar se `.agent/harness/assert-task-skills.py` e `.agent/harness/skill-map.json` existem.
   - Rodar `node <kit>/scripts/check-skills.mjs --root <projeto>` (se existir manifest/lock).

---

## 3. Decisão com o Humano (HITL)

Apresente um resumo curto do diagnóstico (tabela `OK` / `Faltando` / `Atenção`) e confirme com o usuário antes de aplicar mudanças:

1. **Modo de Gateway**:
   - **Gateway compartilhado** (ex.: `https://ai.sigapro.com/v1` + chave do usuário)
   - **OmniRoute Local** (`http://localhost:20128/v1` + chave local; subir Docker se necessário)
2. **Escopo da Instalação**:
   - Somente runtime global (`install.sh`: `omp`, `spec-critic`, `/sdd-loop`, `the-fool`)
   - Global + Bootstrap de projeto atual (`project-overlay/` + `tlc-spec-driven` via `npx skills add tech-leads-club/agent-skills -s tlc-spec-driven -a universal -y` + `reapply-tlc-overlay.py`)
3. **Skills de Stack e Scaffolds** (quando o projeto não tem `.agent/rules/` nem `.agent/harness/tools/`):
   - Perguntar se o usuário quer manter apenas o overlay SDD genérico (`tlc-spec-driven` + `skill-map.json` mínimo) **ou** gerar/copiar regras e tools de scaffold específicas da stack detectada (ex.: Next.js, NestJS, Go, Expo, RN, Rust).

---

## 4. Plano de Execução (Após Aprovação)

1. **Runtime Global**: rodar `./install.sh` (ou copiar `omp/`, `commands/`, `skills/` preservando backups).
2. **Projeto (se aplicável)** — rodar o script idempotente:
   `./scripts/apply-project-overlay.sh <projeto> [--in-agent-dir] [--with-qa]`
   (ele preserva `rules/`, `skill-map.json` e `skills-lock.json` se já existirem, adiciona `.agents/` ao `.gitignore`, instala `tlc-spec-driven` + opcionalmente `qa-report`/`qa-execution`, e reaplica o hook de `assert-task-skills.py`).
   Ajustar `.agent/harness/skill-map.json` para as skills da stack do projeto.
   - Se houver `skills-lock.json`, rodar `npx skills experimental_install --frozen-lockfile`.
3. **Verificação Final Obrigatória**:
   - `node <kit>/scripts/check-skills.mjs --root <projeto>` → `PASS`.
   - `python3 <projeto>/.agent/harness/assert-task-skills.py --root <projeto>` (se já houver `.specs/features/*/tasks.md`).
   - Teste smoke no `omp` com o modelo primário configurado (sem imprimir chaves).

---

## 5. Como o Usuário Invoca Este Arquivo

```bash
# Dentro do clone de omp-harness-kit ou passando o caminho no projeto alvo:
omp "Leia ~/code/omp-harness-kit/.llms.md, diagnostique meu ambiente e este projeto, e me guie na configuracao."
```
